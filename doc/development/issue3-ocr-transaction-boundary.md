# #3 OCR 长事务治理：事务边界与一致性约定

基线：`88206ff7188f930e420a80142409ee40cc98bf57`。施工分支：`fix/20261106-issue3-ocr-transaction-boundary`。

## 外部契约与明确的行为调整

- 保持同步 `POST /api/persons/idcard-image`、原 `PersonIdCardImageView`、`SUCCESS / FAILED / SKIPPED` 三态及权限入口；没有 MQ、公开接口增加、迁移或新业务状态。
- **经用户确认，同上传者未绑定草稿采用幂等复用**：已有记录就是最终结果，后续重复上传不再 OCR，`skipOcr` 的变化不覆盖既有状态；返回数据库真实结果。跨上传者及已绑定图片仍返回冲突。
- 显式跳过才是 `SKIPPED`；远程失败、超时、不可用、非法响应为 `FAILED`。空结果、非法身份证号、非法日期或置信度不能伪装 `SUCCESS`。
- 原上传回填中的明文字段权限语义保留；详情读取继续依据上传者、人口 DataScope 和 `sensitive-data:view-full`。数据库掩码字段无论调用者权限都强制脱敏。

## 新旧事务边界

旧实现：一个 `@Transactional` 包含保存文件、插入草稿、远程 HTTP OCR、结果更新和审计；OCR 等待期间占用事务和连接。`recordAudit` 的同类自调用使 `REQUIRES_NEW` 未生效，且吞审计异常可能误报成功。

新实现的同步调用顺序：

1. 上传编排使用 `Propagation.NEVER`。带外部事务的调用在创建文件前被拒绝，不以“暂停事务”掩盖仍被占用的外部连接。
2. 事务外保存本请求的随机独占文件并计算 SHA256。
3. 通过独立协作组件 `IdCardImageTransactions.reuse` 的真实 `TransactionTemplate` 短事务，锁定已有 SHA 行、检查上传者和未绑定状态；存在则记录必要审计并幂等返回。
4. 没有记录时，结束查询事务，再执行 OCR。此时不占用数据库事务、连接或业务锁，数据库中没有该请求产生的可绑定草稿。
5. OCR 完成后，通过显式短事务插入草稿、写入最终结果及必要审计，然后提交。SQL 中初始 `SKIPPED` 与最终更新处于同一事务，**不会提交供外界绑定的临时状态**。
6. `PersonService` 创建人口时在原有事务中使用 `SELECT ... FOR UPDATE` 读取最新影印本，并在同一锁保护范围完成归属、绑定状态和身份证一致性检查及绑定。

必要审计与对应结果共用真实短事务；审计插入异常或影响行数不为 1 会回滚。私有审计方法不再声称独立 `REQUIRES_NEW`。

组件为这些短事务局部创建 `DataSourceTransactionManager`，显式关闭提交失败后的回滚推断，并设置 `REQUIRES_NEW`；不注册或替换应用默认事务管理器。动态故障注入发现，默认 `JdbcTransactionManager` 会把某些提交异常翻译为运行时数据访问异常，随后尝试回滚并报告 `ROLLED_BACK`，而数据库可能实际已经提交。局部普通 JDBC 管理器将提交 SQL 异常保留为 `TransactionSystemException`，完成状态为 `UNKNOWN`，避免把不可靠的回滚标签当作删除许可。

## 并发首次上传与后续幂等上传的区别

**不保证并发首次上传恰好执行一次 OCR。** 两个请求在记录尚未建立时，允许各自在事务外执行远程识别。

现有 `file_sha256` 唯一约束负责数据库仲裁。胜者提交后，失败方的插入事务必须先完整回滚，再开启新短事务读取胜者，复查上传者和绑定状态；合法时返回胜者真实结果，否则拒绝。失败方不覆盖胜者 OCR，不修改胜者文件引用，不删除胜者文件。已经存在草稿后的重复上传不再执行 OCR。

不使用进程内锁假装实现跨实例去重，也不在数据库锁内等待远程 OCR。

## 文件所有权与正常异常补偿

- 每次保存使用随机文件名和 `CREATE_NEW`，同 SHA 的请求仍拥有不同物理文件；补偿依据本请求独占路径，不能按 SHA 删除。
- 输入流读取及关闭在创建文件前完成。部分写入失败只清理本次已经成功独占创建的文件；独占创建失败不能获得删除既有文件的权限。
- 合法复用、冲突拒绝、确定回滚的插入/审计/提交失败，清理本请求新文件。复用失败不会破坏既有草稿和文件。
- 使用真实事务 `afterCompletion` 观察本次写事务结果。只有未开始写入或明确 `ROLLED_BACK` 才可以丢弃本请求文件；`COMMITTED` 和 `UNKNOWN` 都保留。
- 文件删除也失败时，返回明确补偿失败，不返回成功；日志仅记录固定事件和随机文件名，供人工定位。不能宣称所有文件系统故障均可自动恢复。

## 崩溃与提交结果不明的已知限制

**正常异常补偿不等于进程崩溃后的自动恢复。** 当前没有持久化恢复日志、事务外盒或文件回收任务，也未新增这些机制。

进程在文件写入后、事务前崩溃，断电，或数据库提交确认丢失，都可能留下未引用文件。内存中的事务完成观察不能跨进程恢复。提交结果不明时，数据库可能实际已提交，也可能没有提交；两种情况都必须保留文件并返回处理失败，不能猜测删除。人工处置需另行核实文件归属、事务最终结果和引用，再按文件安全规则授权；本变更不提供自动清扫保证。

部署前应排空旧版本正在执行的上传请求，避免混用旧版可重新 OCR 的草稿语义。没有实施部署或验证混合版本滚动升级。

## 敏感信息

远程响应正文、异常敏感正文不进入错误响应或操作审计。`ocr_raw_json` 仅保留固定脱敏标记，不持久化姓名、地址、身份证号或提供方嵌套原始字段。必要结构化识别字段仍按原业务需求保存，受原权限与脱敏语义约束。审计错误仅记录稳定错误码；持久化及补偿故障日志不打印 SQL、原始异常正文或 OCR 内容。
