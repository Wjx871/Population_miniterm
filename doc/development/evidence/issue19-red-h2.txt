2. 真实业务流程与数据构造方式
================================================================================

主 RED 场景（cancelDraftReleasesBatchAndNewDraftCanBeCreated）使用完整 HTTP 流程创建
“合法的已完成同市跨区迁出批次”，不是直接伪造 migration_out 行：

    1) household 用户通过 POST /api/auth/login 获取真实 JWT（BCrypt 密码校验通过）；
    2) POST /api/migrations/out/applications 创建 personId=93001、
       migrationType=IN_CITY_CROSS_DISTRICT、toRegionCode=110105 的迁出申请 → 201；
    3) 仅通过 JDBC 写入测试必需材料（IDENTITY_PROOF/HOUSEHOLD_BOOK，状态 VERIFIED），
       随后走真实 Service：POST /api/applications/{id}/submit → 200；
    4) POST /api/approvals/{approvalId}/approve → 200；
    5) POST /api/migrations/out/applications/{id}/execute → 200；
       executeOut 在 MigrationService 内生成 transfer_batch_no 并写入 migration_out，
       该行 business_status=COMPLETED（见下方 ISSUE19_RED_COMPLETED_OUT_ROW）。

    6) POST /api/migrations/in/applications（personId=93001、migrationType=IN_CITY_CROSS_DISTRICT、
       toRegionCode=110105、toHouseholdId=93002、transferBatchNo=<上一步 batch>）创建迁入 DRAFT A → 201；
    7) DELETE /api/applications/{A} 取消 A（household 用户持有 application:edit 权限）→ 200；
    8) 再次 POST /api/migrations/in/applications（同一 transferBatchNo）创建迁入 DRAFT B；
       旧实现实际返回 409（见 §3）。

观察矩阵（existingStatusOccupancyObservationMatrix）中的“已完成迁出批次”采用 H2 直接插入
migration_out 行（business_status='COMPLETED'、migration_type='IN_CITY_CROSS_DISTRICT'，并带
对应 business_application 行以满足外键），仅用于状态占用观察；主 RED 场景完全走真实迁出 HTTP 执行链。
测试 @BeforeEach 清空业务表并重建 person(93001/93002/93003)、household(93001/93002)、
household_member、residence；每个测试方法的 H2 状态互相隔离。
