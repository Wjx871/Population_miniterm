HTTP 对照固定统计概览接口、管理员身份、数据库和负载：闭环并发 8，预热 40 请求，每轮计时 12 秒，三轮交错/反向次序，报告三轮指标的中位数。所有响应除了 generatedAt 外对完整业务 data 做摘要校验，HTTP 200 但返回值错误也计失败。每轮保存前后 JVM、连接池、缓存、路由及 Docker 资源快照；逐请求耗时在 Actions artifact 中。

四组环境中两个 JVM、主从 MySQL、Redis 和 RabbitMQ 一直运行；“单实例”指入口只给 backend-1 分流，backend-2 空闲。因此它是请求路由对照，不是单容器和双容器的资源预算对照。每轮重建两个 JVM，保持一致的启动和预热方式；共享执行器、JIT 和短时间窗仍有噪声，不视为显著性或生产容量证明。

每轮全入口预热 40 次意味着双实例每个 JVM 收到的预热更少，未证明进入稳定 JIT 状态。双实例首轮/次轮/第三轮 P95 为 152.958/87.796/126.990 ms、吞吐为 89.151/169.708/128.625 请求/秒，波动明显；缓存组三轮 P95 为 36.370/34.884/36.991 ms、吞吐为 365.153/369.615/368.790 请求/秒。不能把双实例中位数差异直接解释成架构因果或长期回退。

## SQL 瓶颈与实施

实际查询来自 DashboardMapper.countActiveFloating / StatisticsMapper.countFloatingPopulation：`SELECT COUNT(*) FROM floating_population f WHERE f.status='ACTIVE' AND f.current_flag=1`。

原有 `(current_region_code,status)` 索引无法直接覆盖不带地区条件的全局统计。MySQL EXPLAIN ANALYZE 显示优化前扫描 20,000 行，过滤后 5,000 行；候选 `(status,current_flag)` 改为覆盖索引查找，读取 5,000 个索引项。结果计数均为 5,000。

五次根执行器耗时中位数从 5.43 ms 降至 1.27 ms，降低约 76.61%；这是数据库内耗时，不包含网络、身份校验、其他统计 SQL 和 JSON 编解码，不能将它当成接口整体提速。慢查询表也记录了 10 条相应实验语句。由此新增 `V4_015_floating_statistics_index.sql`，提供同名结构校验、可重复执行和在线建索引参数。索引增加存储与写维护成本；当前实验没有测量写入成本。

## 故障与一致性证据

- Redis 实际命中计数增长，测试 TTL 为 3 秒，等待后键消失；成功更新后失效；版本冲突 409 保持数据库及缓存值；管理员和只读用户看见各自允许的字典结果。
- 本地额外测试在真实 Spring 事务中更新成功后主动回滚，验证提交前旧缓存仍在，回滚保持旧数据与缓存；再次正常提交后才删除缓存。云端版本冲突检查不冒充这项提交后回滚实验。
- 停止一个业务容器后的 20 次 GET 全部 200；首次切换耗时 2009.577 ms，后续约 2.9—3.9 ms。修复了旧轮实验 18/20 成功、2 次 504 的情况，但短窗口成功不保证任意故障零损失，也不覆盖宿主机故障。
- 独立代理试验的两个上游均对写入返回 503，其中一个只对 GET 成功：GET 确实尝试过失败上游再返回成功；POST/PUT/PATCH/DELETE 每种仅一台上游收到一次，原 JSON 请求体保持不变。测试的是代理发送次数，不代替业务幂等或消息投递语义。
- RabbitMQ 管理/AMQP 端口未映射宿主机。合成持久队列和 delivery_mode=2 消息在 broker 重启后仍有积压；监控能读取 ready/unack/consumers，权限分别为 401/403/200。停止 broker 返回 DOWN，普通身份查询仍正常；恢复后队列指标恢复。该合成消息不表示 AI 任务业务已接入。
- 继续通过从库真实路由、延迟下主库写后读、复制追平、从库停机回退、Redis 停机注销与跨实例/重启拒绝旧 Token、共享文件与持久卷、Gzip/缓存头/History 路由等原有检查。

### 日志归档时机修复

复核发现全性能实验反复重建 JVM 后，退出时的 docker logs 只剩最新容器日志；自动诊断只解析到 2 条请求，不能用它声称覆盖先前故障。验证脚本改为在 Redis 故障及共享撤销检查后、任何实例重启/重建前保存 `fault-window.log` 并诊断，要求真实识别 Redis 与从库回退且至少有 10 条请求；新增断言防止再次静默漏掉证据。
