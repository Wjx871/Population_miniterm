## 2. 现有链路

```text
POST /api/assistant/policy/query
 → Java 认证与 population:view 权限
 → PolicyTaskAgentService
   → 规则式意图分类、历史追问改写、查询扩展
   → PolicyAssistantService
     → 中文二元组 BM25 风格评分、标题/章节加权
     → Top 4 片段与启发式 confidence
     → 可选模型组织回答 / 检索摘要降级
   → 引用融合与意图过滤
   → 依据状态、摘要、流程信息、权限内下一步动作
 → ApiResponse<AgentResponse>
```

知识库为 19 篇 Markdown、56 个章节分块。包含 PROJECT_GUIDE 与 SYSTEM_GUIDE，不应直接称为正式法规库。
查询接口实际返回 answerSummary、intent、standaloneQuestion、citations、evidenceStatus、mode、nextActions 等字段。
旧设计文档对公开响应的描述已经滞后，接入以当前 Controller 和实际响应为准。

新增 Python 服务复用相同知识文件，建立确定性词法检索基线。没有替换 Java Agent，也未将模型调用接到正式业务。
OCR 的 Java HTTP 适配存在，但本轮没有接通 OCR 模型，新增文档分析接口返回明确的 503。

## 3. Java 评测条件和结果

- 目标：本机 `http://127.0.0.1:8080/api/assistant/policy/query`。
- 角色：population；脚本自行登录和退出，不保存 token。
- 20 条开发问题：14 条正向、3 条敏感/越界请求、3 条依据不足请求。
- 单并发，每题一次，无预热，按题目顺序运行。结果模式均为 RETRIEVAL_ONLY 或 SAFE_REFUSAL，未观察到模型生成模式。
- 逐条结果保留请求对应 ID、实际响应、HTTP 状态、耗时和自动检查；参考答案与可接受文档保留于数据集。

| 指标 | 本次结果 | 解释 |
| --- | --- | --- |
| HTTP 成功 | 20/20 | 接口能返回，不代表回答正确 |
| 正向文档 Hit@4 | 14/14 | 最终引用中存在相关文档，不是分块 Recall 或答案准确率 |
| 行为形态检查 | 18/20 | 两条应依据不足的请求仍引用了通用文档 |
| HTTP P50 | 23.659 ms | 包含本机请求传输和 Agent 处理 |
| HTTP P95 | 36.284 ms | 单轮诊断样本，不能当作稳定容量或生成延迟 |
| 人工答案正确率 | 未评分 | 不能把 14/14 或 18/20 写成答案准确率 |

题目多为对现有指南的直接提问，命中率存在容易命中的偏向。后续需扩充地区、日期、否定、同义表达、跨文档与独立测试集。

## 4. 发现的问题与后续归属

### AI-001：地区和未来版本约束未落实

- Q19 要求引用 2027 年新规，返回 PARTIAL 并给出通用迁入指南；Q20 要求未覆盖地区的法定期限，返回 SUFFICIENT。
- 没有观察到捏造具体法规条款，但系统未明确识别“没有目标地区/目标时间的依据”，存在过度认可证据的问题。
- 代码原因：检索不按地区/有效期过滤，证据充分性主要来自检索分数和章节数量。
- 后续：王家兴补知识元数据、约束处理和拒答评测；张锦源配合 Java 适配证据状态。先保留本次失败，不修改基线结果。

### AI-002：检索命中，摘要却没有回答关键点

- Q08 家庭户、Q13 无权限、Q14 家庭户关系的摘要主要是“请参考下方政策依据”。
- Q07 的“统一提前多少天”和 Q12 的“OCR 后会否自动提交”在引用中有边界说明，摘要却未直接表达关键限制。
- 代码原因：摘要按固定章节名称筛选，再选择首个片段，不能覆盖所有章节标题或问题侧重点。
- 后续：王家兴提出证据组织与覆盖度规则，张锦源维护 Agent 输出契约，张蕊展示引用和需确认事项。不能只提升向量检索而忽略答案组织。

### AI-003：敏感拒绝的原因在 Agent 摘要中丢失

- Q15—Q17 的 mode 为 SAFE_REFUSAL 且无引用，机器形态检查通过。
- 但 answerSummary 统一变为“当前知识库没有足够依据”，没有保留“越界请求被拒绝”的具体原因。
- 后续：张锦源与王家兴区分拒绝、依据不足和工具故障，保留现有测试并补语义断言；本轮只记录，不修改其负责的 Java 逻辑。

### AI-004：模型生成结果是否透传需另做实测

- 代码上 PolicyAssistantService 会生成 answer，但 Agent 又自行组织 answerSummary，没有直接使用这个 answer。
- 当前未配置模型，因此这里只记录待验证的代码路径风险，不宣称已完成模型调用实验。
- 后续：模型接入时使用可控响应测试，确认最终用户实际看到模型结果还是规则摘要。

## 5. 新增服务的验证和边界

实际 HTTP 验证：健康 200；密钥正确检索 200；未授权请求 401；文档模型未配置 503。
独立 Java 17 客户端也覆盖以上四种情况；Spring Boot 业务集成待张锦源接入。
当前 Python 自动化测试为 29 项通过，包含实际 OpenAPI 的错误响应契约；有一条来自 Starlette TestClient 的依赖弃用提示，未影响测试。测试输出保存在本地 `logs/ai-service-tests.log`，Java 探针输出在 `logs/java-ai-smoke.log`。
服务返回真实引用、源版本和可用日期；缺失日期不补造；没有语义检索、生成或 OCR 时能力开关明确为 false。
词法检索的敏感匹配和阈值是基线启发式，不声称足以解决全部安全或证据充分性问题。

材料样例只验证接口与未来规则的设计：4 组字段数据并不是 4 组可供 OCR 测试的图片。
后续需王家兴与张蕊共同补充虚构扫描件/图像和人工标注，然后才计算识别指标。
